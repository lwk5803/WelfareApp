## 1. 프로젝트 한 줄 소개

사회복지관 직원이 쓰는 **회원 관리 + AI 맞춤 복지서비스 추천** 웹 서비스.
정부 공공데이터(중앙부처·지자체 복지서비스)와 LLM을 결합해 회원 조건에 맞는 복지서비스를 추천하고,
**LLM이 사실을 지어내지 못하도록 "생성(LLM) → 검증(코드)" 파이프라인을 LangGraph로 분리**한 것이 기술적 핵심입니다.
기획부터 외부 테스터 배포, 3차에 걸친 실사용 피드백 반영까지 1인으로 진행했습니다.

## 4. 현재 아키텍처 (2026-09-03 기준)

```
브라우저 (Jinja2 HTML + Tailwind CDN + Alpine.js + 바닐라 JS)
   │  httpOnly 쿠키 세션
   ▼
FastAPI 단일 서버 (main.py) ── 화면 렌더링 + /api/* JSON
   ├─ auth.py ────────── Supabase Auth JWT 검증 (JWKS), staff/admin 권한
   ├─ supabase_db.py ─── Supabase Postgres (clients, profiles)
   ├─ gov_welfare_api.py 공공데이터포털 (XML) + 코드 기반 1차 필터(성별·생애주기·나이키워드·특수자격)
   ├─ address_api.py ─── 카카오 주소검색 (+키워드검색 폴백)
   ├─ recommend_graph.py LangGraph: draft(LLM) → verify(코드) → 재시도≤2 → finalize(LLM)
   ├─ ai_recommend.py ── OpenAI 클라이언트 + 후속 채팅(Function Calling으로 Tavily 웹검색)
   ├─ document.py ────── python-docx 등록서류 생성
   └─ threading + 폴링 ─ AI 추천을 백그라운드 작업으로 실행
```

**핵심 설계 원칙 하나만 기억한다면**: "LLM은 *고르고 이유를 말하는 것*만, 사실(서비스명·기관명·신청방법·문의처·링크)은 *정부 API 원본을 코드가 그대로* 렌더링한다." (`recommend_graph.py` 상단 docstring)

## 5. 문제 해결 사례 (STAR 재료)

포트폴리오/면접에서 가장 설득력 있는 부분입니다. 각 항목의 근거 위치를 같이 적어뒀으니 클라우드 세션에서 코드를 열어 확인하면서 다듬으면 됩니다.

### 5-1. LLM 할루시네이션을 구조로 줄이기 ⭐ (가장 강한 사례)
- **상황**: 공공데이터 후보를 GPT 한 번 호출로 "자격 판단 + 웹검색 + 답변 작성"까지 시켰더니, 조건에 안 맞는 서비스나 사실과 다른 내용이 섞여 나옴 (3차 테스트 피드백 "이상한 서비스를 추천함").
- **행동**: LangGraph로 `draft → verify → 재시도 → finalize` 분리. LLM 출력은 `{servId, priority, reason}` JSON으로 좁히고, 코드가 ① 후보 목록에 없는 ID ② 중복 ③ 빈 사유를 거절 → 사유를 담아 최대 2회 재시도. 사실 항목은 원본 데이터에서 코드가 렌더링.
- **결과**: LLM이 "옮겨 적을 사실"이 없어져 링크·기관명 날조가 구조적으로 불가능. 가짜 draft 결과로 verify 거절을 단위 테스트, 실패→재시도→성공 시나리오를 가짜 클라이언트로 시뮬레이션.
- **근거**: `recommend_graph.py`, `main.py::_compute_initial_recommendations`, DEV_LOG "2026-09-03 — 복지서비스 추천을 랭그래프..."

### 5-2. 모델 업그레이드 후 "조용한 실패" 추적
- **상황**: gpt-4o-mini → gpt-5.5 교체 후 추천이 항상 "맞는 서비스 없음"으로만 나옴. 에러는 한 줄도 안 보임.
- **행동**: 후보 목록이 실제로 채워지는지 스파이 함수로 확인 → draft 노드의 LLM 응답을 예외처리 없이 직접 호출 → `temperature` 파라미터를 이 모델이 지원하지 않아 400이 나는데 `except Exception`이 삼키고 있었음을 발견.
- **결과**: temperature 제거 + 실패 원인을 state에 남겨 화면 경고로 노출. 이어서 "재시도 성공 후에도 옛 실패 기록이 남아 불필요한 재시도가 도는" 두 번째 버그도 시뮬레이션으로 발견·수정.
- **배운 점**: 넓은 `except`는 장애를 숨긴다 → 삼키더라도 원인은 반드시 기록.

### 5-3. 100세 회원에게 아동 서비스가 추천된 원인
- **상황**: 테스터가 100세 이상 회원으로 테스트하자 아이돌봄 등 정반대 서비스 추천.
- **행동**: 실제 API 응답을 조회해 보니 "실종아동 등 보호 및 지원" 같은 서비스의 생애주기 태그(`lifeNmArray`)가 **비어 있음** → 태그만 믿는 필터가 "제한 없음"으로 통과시키고 있었음.
- **결과**: 서비스명 키워드 기반 보조 필터(`matches_age_keyword`) 추가, 양방향(성인↔아동전용, 아동↔노인전용) 검증. UI에도 "나이 100세 이상이 맞나요?" 확인 절차 추가.
- **근거**: `gov_welfare_api.py::matches_age_keyword`, `static/js/recommend.js::renderMemberInfoCheck`

### 5-4. 문서와 다른 공공 API 실제 응답
- 지자체 서비스 상세가 항상 빈 값 → 실제 XML을 직접 받아보니 중앙부처와 **필드명이 다름**(`jurMnofNm`→`bizChrDeptNm` 등) (`8943cca`)
- 지자체 API는 `age` 파라미터를 넘기면 결과가 0건 → 파라미터 제거 후 코드에서 나이 필터
- 응답에 있는데 안 쓰던 문의처 필드(`inqplCtadrList`) 발견 → 두 데이터셋의 하위 태그명까지 달라 각각 매핑 (3차 피드백 "문의처도 보이면 좋겠음")
- 전북만 지자체 서비스 0건 → 2024년 개편 행정구역명 "전북특별자치도" 매핑 누락 (`8943cca`)
- **근거**: `gov_welfare_api.py` 곳곳의 주석, `welfare_search.py::CTPV_NAME_ALIASES`

### 5-5. 보안: 저장형 XSS와 쿼리 필터 인젝션
- **XSS**: 회원 이름·주소를 `innerHTML`에 그대로 넣던 공용 카드 렌더러 → 이름에 스크립트를 넣으면 이 카드를 보는 모든 직원 브라우저에서 실행 가능. `escapeHtml()` 도입, AI 답변은 "전부 이스케이프 후 제목/굵게/링크 패턴만 되돌리기" 방식(`renderChatMarkdown`).
- **필터 인젝션**: 중복확인이 이름·전화번호를 PostgREST `or()` 필터 문자열에 이어붙임 → 쉼표/괄호가 들어가면 쿼리 구조가 깨짐. 조건별 파라미터 쿼리로 분리.
- **다층 방어 사례**: 토큰을 httpOnly 쿠키에 둬서, XSS가 있었어도 세션 토큰 탈취 경로는 이미 막혀 있었음.
- **프롬프트 인젝션**: 웹검색 결과 속 지시문을 따르지 말라는 방어 문구 추가 + 후속 채팅은 코드 검증이 없는 영역임을 한계로 명시.
- **근거**: `24b0025`, `static/js/api.js`, `supabase_db.py::find_duplicates`

### 5-6. 스레드 간 공유 클라이언트 상태 손상
- 로그인 기능 추가 후 "가끔 목록이 비고 등록이 실패, 재시작하면 잠깐 정상" → `@lru_cache`로 공유하던 Supabase 클라이언트를 FastAPI 워커 스레드들이 동시에 사용하며 내부 상태가 꼬임. 요청마다 새 클라이언트로 변경, 연속 등록/조회/삭제 반복 테스트로 재발 없음 확인.
- **근거**: `supabase_db.py::_supabase` docstring, DEV_LOG "2026-08-13 — #2 관련 버그 수정"

### 5-7. CSS 우선순위 두 번 꼬인 버그
- 검색 아이콘이 입력 텍스트와 겹침 → 커스텀 CSS의 `input{padding}`이 Tailwind `pl-9`를 이김 → `:where()`로 우선순위 0 처리 → 이번엔 `border`까지 같이 약해져 입력창 테두리가 사라짐 → "Tailwind에 져야 하는 속성(padding)"과 "이겨야 하는 속성(border)"을 규칙 둘로 분리해 해결.
- **근거**: `static/css/custom.css` 폼 요소 주석

## 6. 기술 선택 근거 요약

상세 버전은 `docs/portfolio/WelfareApp_코드_스터디_노트.pdf`(16쪽) 2장에 있습니다. 공통 논리는 **"직원 몇 명·회원 수백 명 규모에 맞게, 필요한 만큼만"** 입니다.

| 영역 | 선택 | 비교 대상 | 선택 이유 (한 줄) |
|---|---|---|---|
| 백엔드 | FastAPI | Django, Flask | DB/인증은 Supabase가 담당 → Django는 중복, Pydantic 자동 검증이 20개+ 필드 폼에 유리 |
| 화면 | Jinja2 SSR | React/Next.js | 빌드 없음, 서버 하나로 배포, 비전공 운영자가 직접 수정 가능 |
| CSS | Tailwind Play CDN | Tailwind 빌드, Bootstrap | 빌드 단계 제거 (트레이드오프: 프로덕션 비권장 → 규모 커지면 1순위 재검토) |
| 인터랙션 | Alpine.js | React, jQuery | 실제 용도는 사이드바 토글 하나 — 선언형 한 줄로 끝 |
| DB+인증 | Supabase | SQLite, 자체 Postgres | 동시 접속 안전, 비밀번호/JWT를 직접 구현하지 않음 |
| 세션 | httpOnly 쿠키 | localStorage | JS로 토큰 탈취 불가 (XSS 사례에서 실제로 효과) |
| AI 흐름 | LangGraph | while 루프, LangChain 전체 | 재시도 분기를 노드/엣지로 명시. 솔직히 지금 규모에선 필수는 아님(확장 대비 + 학습 목적) |
| LLM | OpenAI(gpt-5.5) + Ollama 옵션 | Claude, Gemini | JSON 응답·Function Calling 안정성, `AI_PROVIDER=local`로 무료 전환 가능 |
| 백그라운드 | threading + 2초 폴링 | Celery+Redis, WebSocket | 추가 인프라 없음, 몇십 초 작업엔 폴링으로 충분 |
| 캐시 | 직접 만든 TTL 캐시 | Redis, lru_cache | lru_cache는 만료 없음, Redis는 과함 |
| 서류 | python-docx | reportlab, HTML→PDF | 현장이 워드로 인쇄·보관, 종이 양식 레이아웃 재현 |
| 차트 | Chart.js | D3.js | 파이/막대 몇 개 수준엔 설정 객체 하나로 충분 |

## 7. 솔직한 한계와 개선 계획 (면접 대비)

- 후속 채팅(`chat_turn`)은 LangGraph 코드 검증이 **적용되지 않는** 자유 대화 → 간접 프롬프트 인젝션 가능성 잔존
- AI 작업 상태·캐시가 서버 메모리(dict) → 재시작 시 소실, 다중 서버 불가
- 사진·서명을 base64로 DB 컬럼 저장 → 회원 수만 명 단위면 Storage로 이전 필요
- Tailwind CDN 방식 → 프로덕션 전환 시 빌드로 교체
- 자동화 테스트 코드(pytest) 없음 — 검증은 curl/TestClient 수동 스크립트로 수행 → **포트폴리오 보강 1순위 후보**
- 실제 브라우저 E2E 검증은 사용자가 수동으로 함
- `stats.py`는 매번 전체 회원을 불러와 pandas로 집계 (DB 집계 쿼리 아님)
- "광주"는 광주광역시/경기 광주시 이름 충돌 (`welfare_search.py` 주석)

## 8. AI 협업 개발에 대해 — 정직하게 쓰는 법

이 프로젝트는 **Claude Code와 협업(바이브 코딩)** 으로 만들어졌습니다. 숨기기보다 이렇게 프레이밍하는 걸 권합니다:

## 10. 클라우드 세션에서 이렇게 시작하세요

클라우드 세션에서는 앱 실행에 `.env`가 필요 없는 **문서·코드 읽기 작업**부터 하는 게 효율적입니다. 예시 요청:

1. "`docs/PORTFOLIO_BRIEF.md`를 읽고, 9장 체크리스트대로 `docs/portfolio/WelfareApp_포트폴리오.pptx` 내용을 업데이트할 슬라이드 원고를 만들어줘"
2. "5장 문제 해결 사례를 STAR 형식 포트폴리오 문장(각 300자)으로 다듬어줘. 코드를 직접 열어 사실관계 확인하면서"
3. "README를 포트폴리오용(스크린샷 자리, 아키텍처 다이어그램, 핵심 사례 링크)으로 개편해줘"
4. "7장의 '자동화 테스트 없음'을 보강하게 `recommend_graph.py`의 verify/retry 로직과 `parsers.py`에 pytest를 추가해줘 (외부 API는 가짜 클라이언트로)" — 포트폴리오 신뢰도가 크게 올라갑니다.
5. "면접 예상 질문 20개와 모범 답안을 이 저장소 근거로 만들어줘"
